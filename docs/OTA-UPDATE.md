# OTA 无感升级实施方案

规划基线：`v0.22.0` / `1c34658`，2026-10-26。本文件是实施计划，当前程序尚未启用网络检查或自动更新。

实施记录：阶段 A 已添加隔离原型 `tools/ota-lab`。Windows 本机通过签名下载、原文件名绑定、错签/截断拒绝及两版本切换回退测试；`self-replace` 缺失候选导致入口消失已复现。后续只评估 `self_update::Move` 的直接替换模式配合独立持久备份，禁止用 `MoveAll` 或 `replace_using_temp` 移走固定 EXE。完整事务和断电/防护软件验收仍是启用门槛，详见原型 README。

## 1. 目标与使用体验

后台发现正式版本、下载并验证，在面板隐藏且操作结束后自动切换，回到托盘。用户正在查看面板、编辑备注或修改设置时继续使用当前版本；可主动选择“重启并更新”。

- 首次启动延后约 2 分钟检查，之后每 12 小时检查一次并加入随机抖动；失败按 15 分钟、1 小时、6 小时退避，遵守服务端重试时间。手动检查可即时发起，同一安装目录只允许一个更新任务。
- 默认只接收正式 stable 版本；草稿、预发布、相同版本及低版本不自动安装。升级过的版本记住最高已接受版本，防止更新源重放旧包。
- 自动更新默认开启，设置提供关闭开关；关闭后停止后续检查与下载。当前 README“默认不联网”需要随首个 OTA 版本改为准确描述，不收集设备数据或遥测。
- 后台下载失败不弹窗打断；设置显示有操作价值的状态和重试入口。签名失败、回退及目录不可写给出简短失败反馈，不显示技术协议说明。
- 用户主动退出就退出，不因待更新而重新启动。已验证的待安装版本留到下一次启动，或之后的后台空闲窗口处理。

“无感”指下载和后台交接不打扰正常操作；进程仍需短暂重启，不能承诺运行中的机器码热替换。更新期间保持窗口隐藏、原有自启意图和配置位置。

## 2. 当前工程约束

| 现状 | 实施要求 |
| --- | --- |
| Windows x64，Rust + Slint，程序资源嵌入 EXE | 更新逻辑放应用层，不向 `periph-hal` 引入网络、发布或 UI 依赖 |
| `Config::path()` 使用 EXE 同级 `config/settings.json` | 主程序固定路径，更新不覆盖 config，不从临时目录启动普通模式 |
| 开机启动快捷方式直接指向当前 EXE | 稳定 EXE 路径不变，重启使用受控参数，不重复创建快捷方式 |
| `Local\\BatteryIsland.v1` 单实例锁与独立 IPC 窗口 | 保留现有兼容标识；更新交接期间另有事务锁，防止双启动争抢 HID |
| 配置通过 saver 线程异步保存，退出会等待 worker | 安装前需要明确的保存成功确认和取消扫描屏障，不能仅投递保存请求就退出 |
| Release 标签触发 CI，先创建草稿，再公开 | 更新器只看到已公开、签名完整且校验通过的版本；发布草稿不触发用户升级 |
| 本机曾出现 Windows error 5 拒绝启动生成的 EXE | Defender/360、目录占用及辅助进程被拦截必须进入实测，不能靠关闭防护完成验收 |

## 3. 现成方案选择

先复用现有库，应用只补调度、健康确认和恢复策略。

| 方案 | 核实到的能力 | 本项目决定 |
| --- | --- | --- |
| [self_update](https://docs.rs/self_update/latest/self_update/) | GitHub 发布发现、下载、ZIP、校验与 zipsign 签名验证；公开下载/验证及 `MoveAll` 接口 | 推荐主方案，关闭终端确认和输出，选择必要 features，在专属阻塞线程运行 |
| [self-replace](https://docs.rs/self-replace/latest/self_replace/) | Windows 等平台的运行中 EXE 自替换和清理 | 做原型对照；不把成功替换文件等同于新版本启动健康 |
| [Velopack Rust](https://docs.velopack.io/getting-started/rust) | Rust SDK、便携更新及完整包生命周期 | 保留为备选；采用后需迁移目录、配置和启动定位，不能直接套入当前同级配置布局 |

Velopack 的 Windows 更新会替换 `current`，配置应移到其外；文件占用时还可能结束相关进程或弹出处理窗口。[官方 Windows 说明](https://docs.velopack.io/packaging/operating-systems/windows)、[配置保留说明](https://docs.velopack.io/integrating/preserved-files)。这些行为需要额外适配，才能符合本项目“忙时延后”的体验。

主方案采用 `self_update` 的发布、下载、验证和文件事务原语，避免使用一键 `update()` 同时决定安装与重启。`MoveAll` 的失败回退不是断电恢复保证；应用必须有持久事务记录和启动恢复。也不把更新库描述成自带启动崩溃回退。

**阶段 A 的关键决策门槛是固定启动入口可恢复。** 若切换做法先挪走旧 EXE，再放入新 EXE，中间断电会导致正常入口消失，届时“下次启动读事务记录”无法自行发生。必须验证所选替换原语能保持有效入口，或采用库提供的稳定启动/恢复器；不能只依赖存活中的维护进程。人工运行备份仅作应急，不能算无感恢复验收通过。若这一点需要自建常驻启动器才能满足，优先切换 Velopack，而不是继续扩大自制更新框架。

阶段 A 的原型若无法用现有原语满足文件恢复、被拦截后保留旧程序等门槛，应改用 Velopack 并更新本决策，不自行重写 Windows 自替换底层、ZIP、HTTP 或密码算法。

## 4. 目录和模块

```text
程序目录/
  periph-in-one.exe              固定入口
  licenses/                     发行管理的许可文件
  config/
    settings.json               原业务配置
    update-settings.json        自动更新偏好，独立于业务 schema
  .ota/
    state.json                  下载缓存状态与持久事务记录
    <transaction>/
      package.zip               保持发行资产原文件名，用于验签
      staged/                   验证后的候选程序与许可文件
      backup/                   本轮旧程序、许可及配置检查点
      agent.exe                 当前可信程序复制出的维护模式
```

示意中的 `package.zip` 是角色名；实际落盘名保留发行文件名，避免破坏签名的文件名绑定。暂存、备份与目标目录位于同一文件系统；下载不写正式 EXE。

- `src/update/`：状态机、发布源、下载验证、调度、事务与恢复。逻辑可用伪发布源、伪时钟和临时目录测试。
- `src/platform/update.rs`：Windows 进程句柄、隐藏维护进程、事务锁、就绪通信。复用现有 windows-sys；路径与参数作为结构化参数传递，不拼接 cmd/PowerShell 命令。
- `src/main.rs`：在 Slint 初始化和普通单实例检查之前识别内部维护/预检入口。
- `src/app.rs`：更新事件、保存屏障、用户交互状态、重启窗口。硬件读取线程与网络更新线程独立。
- `ui/app.slint`：当前版本、自动更新开关、检查更新；准备完成才出现“重启并更新”。不常驻展示步骤、签名或接口约束。

维护模式只处理本安装目录中经验证的事务；不接受任意目标路径和任意可执行命令。事务中路径、版本、大小和哈希都需重新验证。

## 5. 发布协议与真实性

保留人工下载的完整 ZIP；另生成 OTA 专用 ZIP，包含主程序、该构建的依赖许可和 `ota.json`。两种包来自同一份构建，不重新编译。首版使用全量包，当前体积无需先引入差分更新。

`ota.json` 随 ZIP 一起签名，至少绑定：应用 ID、版本、目标平台 `x86_64-pc-windows-msvc`、更新协议版本、所需最低更新器版本、可读取配置 schema 范围，以及负载文件名、大小和 SHA256。候选程序预检再次核对内置版本和平台。

GitHub tag、资产名及外层 JSON 只能作为发现提示；安装判定以验签后的包内信息为准。签名有效但应用、平台、版本或协议不匹配同样拒绝。客户端不携带 GitHub 私人令牌。

- SHA256 用于完整性检查；发布身份由内置公钥验证的签名确认，不能仅信任随下载包一起取得的 SHA256SUMS。
- 复用 self_update 的 `signatures` / zipsign 验证入口，强制公钥集合非空；不存在“无公钥就跳过”的降级路径。[签名 API](https://docs.rs/self_update/latest/src/self_update/update.rs.html)
- 私钥不进仓库、不进入客户端或普通 PR CI。发布专属受保护环境保存签名凭据，签名 job 只签本次受信标签构建并核验过的产物。
- 密钥轮换采用过渡版本双签，并先让客户端获得新公钥；旧公钥客户端仍可验证过渡包。[公钥与轮换说明](https://docs.rs/self_update/latest/src/self_update/lib.rs.html)
- 包内路径使用固定白名单，拒绝绝对路径、`..`、符号链接/reparse 跳转及超出解压限制的内容。EXE、许可目录之外不接受写入，尤其禁止覆盖 config、更新偏好、事务目录和其他用户文件。

下载有连接、读取和总时限，限制压缩及解压总大小；预检空间和目录写权限。网络失败保留现用版本，使用系统允许的代理策略，不切换到未经配置的第三方代理或镜像。

## 6. 从发现到切换

```text
Idle → Checking → Downloading → Verified → WaitingForIdle
                                                ↓
                                            Preparing
                                                ↓
                                             Applying
                                                ↓
                                           AwaitingHealth
                                           ↙           ↘
                                      Committed      RolledBack
```

1. 独立线程后台查询公开 stable 发布，比较语义版本和签名协议兼容性。未下载完、未验签或未预检的候选不能进入 WaitingForIdle。
2. 候选新 EXE 以受限 `--ota-probe` 模式执行：不获取硬件、不展示 UI、不改配置，只返回内置版本、协议和使用临时副本进行的配置加载/迁移结果。必须先验签再执行。
3. 面板隐藏至少 30 秒、无备注/设置操作且保存成功后进入 Preparing。窗口重新打开、保存失败或准备超时就延期；用户手动选择更新时走相同准备流程。
4. 暂停新刷新请求，取消当前等待，确认保存队列已落盘；建立旧程序/许可与配置检查点，写入并刷盘事务记录。拿到维护进程已就绪确认后才退出主程序。
5. 维护进程隐藏运行，通过继承/复制的进程句柄等待旧进程实际结束，避免单纯 PID 轮询和 PID 复用。旧进程未退出则不替换，不强行终止其他应用或安全软件。
6. 维护进程使用阶段 A 验证过的切换原语处理 EXE 和许可，保留持久备份。EXE 作为最终提交点，不能直接假定一组普通 rename 就是断电原子事务。主程序路径保持不变；普通双击启动检测到未完成事务时等待恢复，不能绕过事务锁抢先启动。
7. 从正式路径启动新版本，携带一次性就绪凭据，保持托盘隐藏状态。新进程先取得原单实例锁，再建立 UI/托盘、加载配置并确认事件循环可响应。
8. 启动健康窗口建议 30 秒。健康判据不依赖外设在线或电量读取成功；缺少设备、蓝牙离线和后端超时不能触发程序降级。
9. 健康确认前，新进程不把迁移或业务保存写入正式配置，待保存操作保持队列状态，也不提前提示“已保存”。收到事务提交确认后才开放保存。
10. 新进程崩溃、无法启动或未在期限内确认，维护进程只处理自己启动的候选进程，恢复旧 EXE/许可并从正式路径启动旧版。这仅允许恢复本事务哈希绑定的可信旧版，不构成更新源可任意降级的入口。旧配置在此期间未被改写；若出现不符合预期的并发配置修改，保留原文件与备份，不盲目覆盖。

更新就绪不意味着必须立即安装。关闭自动更新、用户主动退出、窗口活动或保存失败都优先服从用户当前操作。

## 7. 失败与恢复边界

| 场景 | 期望结果 |
| --- | --- |
| 断网、限流、GitHub 不可达 | 继续旧版本，限频重试；手动检查显示失败反馈 |
| 包损坏、签名/版本/平台不符 | 不执行、不切换；标记该候选失败，不反复下载同一坏包 |
| 目录不可写、空间不足、文件被占用 | 留在旧版本，延后安装；不自动提权或结束外部进程 |
| 辅助程序被安全软件拦截 | 旧进程在维护就绪确认前不退出；未完成事务可恢复 |
| 替换后新程序启动失败 | 恢复旧文件与原配置，记录本次版本失败，停止自动重试该版本 |
| 断电或任一交接进程被结束 | 下次启动读持久状态，校验文件哈希后完成或撤销事务，不只依据文件名猜状态 |
| 用户更新前退出 | 不重新唤起应用；下次启动再处理已验证候选 |
| 更新提交后较长时间才发现业务缺陷 | 不承诺自动回退；跨 schema 降级需单独兼容策略，不能直接恢复过时配置而丢失新备注 |

首次上线前定义每个文件变更点的恢复规则，尤其是 canonical EXE 暂时不存在时仍可通过维护备份恢复。保留最近一个可恢复版本，成功后的清理可重试；不能为清理失败反复重启程序。

诊断信息仅存本地、限大小和轮转，记录更新阶段及错误类别，不写设备序列号、蓝牙地址或整份用户配置；用户可主动导出。

## 8. CI/CD 调整

1. 延续现有 fmt、Linux HAL、Windows all-targets、Clippy、Release 构建检查。
2. 从同一 EXE 生成完整便携 ZIP 和 OTA ZIP，产生包内版本清单及负载哈希。
3. 在受保护签名 job 中签 OTA ZIP；使用客户端相同公钥和验证函数复验。签名完成后再生成外层 SHA256SUMS，禁止签完之后改包或改文件名。
4. 上传两个 ZIP 与校验文件至 Release 草稿；验证签名和 OTA 资产齐全才允许公开。缺失 OTA 的发布可供手动下载，但客户端不得退回安装未签名完整包。
5. 发布前在 Windows 验证“上一已发布版本 → 候选版本 → 启动健康确认”；另做坏包、异常退出及回退场景。自动化通过不替代安全软件与便携目录的真机检查。
6. 公开发布后客户端才能发现；已公开资产保持不可变。紧急撤回使用发布撤回和客户端失败版本隔离，已下载候选在安装前再检查公开状态；未来确需远程撤销已缓存版本时增加签名撤销元数据，不能声称删除 Release 可以瞬间收回离线缓存。

Authenticode 可作为降低 SmartScreen/安全软件阻力的独立发行改进；它与客户端验包签名用途不同，不能相互替代，也不能承诺签名后完全不拦截。

## 9. 分阶段落地与提交

| 阶段 | 成果 | 合入门槛 / 提交 |
| --- | --- | --- |
| A：选型原型 | 固定依赖版本和最小 features；两个测试版本完成下载验签、隐藏交接和文件回退；比较发布包体积 | 中文/空格路径、单实例锁、安全软件拦截和维护进程启动失败可控，证明所选库满足方案；独立提交 |
| B：签名发行 | OTA 包、包内清单、公钥、受保护签名 job、发布草稿检查 | 客户端拒绝无签名/错签名/错平台/低版本/坏包；无发布私钥泄露到 PR；独立提交 |
| C：后台准备 | 状态机、独立线程、检查节流、下载与预检、设置入口 | 离线与下载不阻塞 UI/HAL，关闭开关有效，不重复并发下载；独立提交 |
| D：安全交接 | 保存屏障、维护模式、事务记录、正式路径重启与健康确认 | 每个事务阶段结束进程可恢复，失败保留旧配置；提交前通过升级/回退矩阵 |
| E：正式启用 | 更新文档、发行说明、真实便携目录及防护软件验收 | 两个实际发布构建之间完整验证，通过后再在 stable 默认开启；独立提交 |

测试重点：磁盘不足、只读目录、下载截断、ZIP 路径穿越和解压膨胀、断电恢复、中文/空格路径、杀毒隔离、重复启动、编辑中触发更新、保存失败、旧 v1/v2 配置、启动慢/启动崩溃、无外设/蓝牙离线，以及用户退出后不复活。文件切换与健康测试使用测试程序和临时目录，不改用户真实程序或配置。

## 10. 首次交付顺序

`v0.22.0` 没有更新器，不能凭发布新版本让已安装旧程序自行升级。用户需要手动下载一次带更新器的版本；后续版本才能通过 OTA 送达。

建议先发布包含实现但默认关闭的测试版，使用下一测试构建验证真实跨版本升级、失败回退和配置保留，再发布默认开启的 stable 引导版本。stable 引导版本号实施时确定，不预先占用标签。首个自动更新目标必须已完成签名发行和跨版本验收。

规划文件提交不修改当前更新行为，不生成签名私钥、不配置远端 Secrets，也不发布新版本。
